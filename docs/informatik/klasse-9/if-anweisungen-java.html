Dein Tag steckt voller Entscheidungen

Du triffst ständig Entscheidungen – meist ohne es zu merken:

Wenn es regnet …

… nimmst du den Regenschirm mit.
Wenn nicht, lässt du ihn zuhause.

Wenn der Boss nur noch wenig Leben hat …

… setzt du den finalen Angriff.
Wenn nicht, weichst du aus.

Muster erkannt? Immer wenn eine Bedingung erfüllt ist, passiert etwas – sonst etwas anderes (oder nichts). Genau das bringen wir dem Computer jetzt bei!

Die einfachste if-Anweisung

// Allgemeine Form if (Bedingung) { // wird nur ausgeführt, // WENN die Bedingung wahr ist }
// Konkretes Beispiel int alter = 15; if (alter >= 16) { System.out.println("Du darfst den Moped-Führerschein machen!"); }
💡 Lies es wie einen Satz: „WENN alter mindestens 16 ist, DANN gib den Text aus.“ Die geschweiften Klammern { } umschließen alles, was bei „wahr“ passieren soll.

Das Struktogramm macht die Entscheidung sichtbar

Im Struktogramm gibt es keine Pfeile – alles läuft strikt von oben nach unten:

1

Kopf: Die Bedingung steht im Dreieck ganz oben.

2

Zweige: Links alles bei wahr, rechts bei falsch – die Bezeichnungen stehen über dem Trennstrich.

So liest du es: Ist die Bedingung wahr, läuft der linke Zweig. Bei falsch passiert hier nichts – das Programm läuft am leeren Zweig vorbei und macht einfach weiter.

Unsere Beispiel-Klasse: Spielcharakter

Wir bauen den Helden für ein Jump'n'Run – und die if-Anweisung steckt in der Methode trefferErleiden():

public class Spielcharakter { // Attribute private String name; private int leben; private int punkte; // Konstruktor public Spielcharakter(String nameStart, int lebenStart) { name = nameStart; leben = lebenStart; punkte = 0; } // eigene Methode: nur lebende Helden kassieren den Treffer public void trefferErleiden() { if (leben > 0) { leben = leben - 10; System.out.println(name + " hat noch " + leben + " Leben."); } } }
💡 Vor jedem Treffer prüft das Programm: leben > 0 – also „hat der Held noch Leben?“. Nur wenn die Bedingung wahr ist, werden die beiden Anweisungen im Block ausgeführt.
Teste dein Verständnis: Was passiert, wenn held.trefferErleiden() bei leben = 0 aufgerufen wird? Und warum ist das sinnvoll?

Achtung, Klassiker: = ist eine Zuweisung (nameStart = "Ryu"), == ist ein Vergleich (punkte == 100). Verwechseln = Lieblingsfehler von Anfängern und Profis! 😉

if – else: Zwei Wege

Oft soll bei „falsch“ auch etwas passieren – dafür gibt es else:

// Beispiel: Level-Aufstieg int punkte = 120; if (punkte >= 100) { System.out.println("Level geschafft!"); } else { System.out.println("Noch ein bisschen weiter!"); }
💡 else bekommt keine eigene Bedingung! Es ist der sonst-Fall – im Struktogramm der rechte Zweig. Genau einer der beiden Blöcke wird immer ausgeführt.

else if: Mehrere Fälle – live durchklicken

Vier Startwerte, vier Ränge: Drücke → und beobachte Code und Konsole!

// Rang je nach Punktestand int punkte = 150070035040; if (punkte >= 1000) { System.out.println("Rang: LEGENDE"); } else if (punkte >= 500) { System.out.println("Rang: GOLD"); } else if (punkte >= 100) { System.out.println("Rang: SILBER"); } else { System.out.println("Rang: BRONZE"); } // nach der if-Anweisung läuft das Programm weiter: System.out.println("Statistik gespeichert – weiter im Spiel!");

💡 Java prüft von oben nach unten – nur der erste wahre Block läuft, der Rest wird übersprungen. Und ganz wichtig: Danach läuft das Programm normal weiter – die letzte Ausgabe kommt in jedem der vier Fälle!

Vier Klassiker-Fehler

= statt ==

if (punkte = 100) ❌  →  if (punkte == 100) ✓

Semikolon nach if

if (a > b); { ... } ❌  →  das ; beendet die if-Anweisung sofort – der Block läuft dann immer!

Vergessene Klammern

Zur einzelnen Anweisung dürfen die { } wegfallen – aber lieber immer setzen! Sonst überraschen dich später Fehler.

Text vergleichen mit ==

Für Strings nimmt man name.equals("Ryu") statt name == "Ryu".
